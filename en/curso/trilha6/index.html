🏋️ Ready-to-use exercises

Six guided challenges, one for each stage of the cycle. Each includes an objective, step-by-step instructions, a “done” criterion, and a sample answer key.

What it is:

Identification exercise: given the profile of a fictional company, find three repetitive tasks that add up to ~10 hours per week.

Why learn:

Seeing opportunities is the most valuable skill in the cycle. Without raw material (the right task), there’s no point in automating anything.

Key concepts:

Frequency × duration × pain; “10-hour” task; completion criteria; annotated answer key.

What it is:

Measure the current process time and cost, and calculate the return on automating it using a spreadsheet template.

Why learn:

ROI is the number that justifies the project to you and sells it to the client. Without it, it’s just “guesswork”.

Key concepts:

Cost/hour; hours/month; annual savings; payback; ROI formula.

What it is:

Map the current process (as-is) step by step and the automated version (to-be), marking what the AI takes on.

Why learn:

The diagram reveals bottlenecks and shows exactly where automation fits—it becomes the project scope.

Key concepts:

Manual × automatable steps; decision point; simple notation with text/arrows.

What it is:

Starting from the to-be, specify the trigger, tools, AI model, logic, and actions in a one-page blueprint.

Why learn:

The blueprint is the bridge between idea and implementation. Those who design well build quickly and avoid rework.

Key concepts:

Trigger; nodes; model; conditional logic; final action; failure points.

What it is:

Actually build a 3-node workflow: a trigger, an AI call, and an output action.

Why learn:

The first end-to-end automation unlocks everything: after that, you just repeat the pattern with variations.

Key concepts:

Trigger; prompt in the workflow; response parsing; action; test with real data.

What it is:

Turn the automation you built into a 1-page proposal: problem, solution, ROI, price, and next steps.

Why learn:

Building without knowing how to sell leaves money on the table. The proposal completes the material's journey by turning it into a commercial deliverable.

Key concepts:

Value-based pricing; proposal structure; ROI anchoring; clear CTA.

📋 Prompt library

Six complete prompts, ready to copy and paste. Each includes the full text, usage instructions, and the variables to replace.

What it is:

Prompt that takes a process description and returns steps, estimated times, and automation candidates.

Why learn:

Speeds up the audit phase from hours to minutes and standardizes the output.

Key concepts:

Role + context; output format; variables {{processo}} and {{setor}}.

What it is:

Prompt that lists and ranks automation opportunities by effort × impact.

Why learn:

Helps you choose where to start—the most common mistake is automating what doesn't matter.

Key concepts:

Effort × impact matrix; quick wins; cut criteria.

What it is:

Prompt that takes the objective and returns suggested triggers, tools, model, logic, and actions.

Why learn:

Gets the blank page out of the way and gives you an architecture draft to refine.

Key concepts:

Explicit constraints; available stack; output in blocks.

What it is:

Prompt that generates the conditional logic / pseudo-config for an automation node based on the business rule.

Why learn:

Translates a rule in text into implementable logic, reducing transcription errors.

Key concepts:

If/else; field mapping; exception handling.

What it is:

Prompt that extracts fields from free-form text and returns valid JSON with a fixed schema.

Why learn:

Reliable JSON is what connects AI to the rest of the workflow; without it, the automation breaks.

Key concepts:

Schema; “respond with JSON only”; null for missing values; validation.

What it is:

Prompt that builds a complete sales proposal from the problem, solution, and ROI.

Why learn:

Generates a sellable first version in seconds that you only need to adjust.

Key concepts:

Tone; structure; value anchoring; {{cliente}} and {{preço}} variables.

🧩 Ready-made skills

Reusable skill/automation templates. Each topic includes the template in a code box, when to use it, and customization points.

What it is:

The parts every well-made skill has: input, instructions, rules, output format, and examples.

Why learn:

Understanding the anatomy lets you create new skills in minutes using the same skeleton.

Key concepts:

Input; role; rules; output; few-shot; versioning.

What it is:

A skill that reads a message, classifies it into categories, and decides where to send or route it.

Why learn:

Triage is one of the highest-ROI automations and one of the most requested by clients.

Key concepts:

Closed categories; confidence; "human" fallback; JSON output.

What it is:

A skill that receives a long document and returns a summary + structured fields.

Why learn:

Contracts, notes, and PDFs are an endless source of repetitive manual work.

Key concepts:

Chunking; target fields; source citation; output schema.

What it is:

A skill that receives tabular data and generates a narrative report with highlights and recommendations.

Why learn:

Turns raw numbers into a communicable insight—a deliverable the client immediately sees value in.

Key concepts:

Key metrics; period-over-period change; executive tone; fixed sections.

What it is:

A skill that answers questions using only a provided knowledge base (RAG pattern).

Why learn:

Support grounded in the source prevents hallucinations and is the most marketable use case today.

Key concepts:

Context recovered; "answer only from the knowledge base"; cite a passage; "I don't know".

What it is:

How to take a template and adapt it to a new client without breaking it, while keeping version history.

Why learn:

Reuse is what scales an automation business: you never start from scratch.

Key concepts:

Customization points; changelog; v1→v2; regression tests.
