🧬 Anatomia de uma skill reutilizável

Toda skill bem-feita tem as mesmas partes. Decore este esqueleto e você cria skills novas em minutos.

SKILL: {{nome_da_skill}}            # v1.0
PAPEL:    Você é {{especialista_em_X}}.
OBJETIVO: {{o_que_a_skill_entrega}}.

ENTRADA (variáveis):
  - {{var_1}} : descrição
  - {{var_2}} : descrição

REGRAS:
  - {{regra_1}}
  - {{regra_2}}
  - Quando não tiver certeza: {{fallback}}.

FORMATO DE SAÍDA:
  {{schema_ou_estrutura}}

EXEMPLO (few-shot):
  entrada -> {{exemplo_in}}
  saída   -> {{exemplo_out}}

ENTRADA REAL:
"""
{{entrada}}
"""

Quando usar

Sempre que for transformar um prompt solto em algo reutilizável e versionável. É o molde das quatro skills seguintes.

Pontos de customização

  • PAPEL e REGRAS — específicos do domínio
  • FORMATO — schema da saída
  • EXEMPLO — 1–2 casos do cliente

📨 Skill: classificar e rotear e-mails/mensagens

Lê uma mensagem, classifica em categorias fixas e decide o destino.

SKILL: Classificar & Rotear            # v1.0
PAPEL: Você é um classificador de mensagens de atendimento.

REGRAS:
  - Categorias permitidas: {{categorias}}   // ex: pedido, dúvida, reclamação, spam
  - Escolha SOMENTE uma categoria da lista.
  - Dê uma confiança de 0 a 1.
  - Se confiança < 0.6, destino = "humano".

FORMATO DE SAÍDA (apenas JSON):
  { "categoria": string, "confianca": number,
    "destino": string, "resumo": string }

Mensagem:
"""
{{mensagem}}
"""

Quando usar

Triagem de caixa de entrada, WhatsApp, tickets. Coloque na frente de qualquer fluxo que precise decidir "para onde isso vai".

Pontos de customização

  • {{categorias}} — as do cliente
  • Limiar de confiança (0.6) por tolerância a erro
  • Mapa categoria → destino no fluxo

📄 Skill: resumir e extrair dados de documentos

Recebe um documento longo e devolve resumo + campos estruturados, citando a fonte.

SKILL: Resumir & Extrair Documento     # v1.0
PAPEL: Você extrai dados de documentos com precisão.

REGRAS:
  - Use SOMENTE o que está no documento. Não infira.
  - Para cada campo extraído, cite o trecho de origem.
  - Campo ausente = null.

FORMATO DE SAÍDA (apenas JSON):
  {
    "resumo": string,                  // 3 a 5 linhas
    "campos": { {{campos_alvo}} },     // ex: "valor", "vencimento", "partes"
    "citacoes": { "campo": "trecho..." }
  }

Documento:
"""
{{documento}}
"""

Quando usar

Contratos, notas fiscais, propostas, e-mails longos. Para documentos grandes, divida em pedaços (chunks) e rode por parte.

Pontos de customização

  • {{campos_alvo}} — o que extrair
  • Tamanho do resumo
  • Ligar/desligar citações

📈 Skill: gerar relatório a partir de planilha

Recebe dados tabulares e gera um relatório narrativo com destaques e recomendações.

SKILL: Relatório de Planilha            # v1.0
PAPEL: Você é um analista que vira dados em insight executivo.

DADOS (CSV/tabela):
"""
{{dados}}
"""
Período: {{periodo}}   ·   Métricas-chave: {{metricas}}

REGRAS:
  - Baseie-se SÓ nos números fornecidos.
  - Destaque variações relevantes (subiu/caiu) com o número.
  - Tom executivo, direto. Sem jargão.

FORMATO DE SAÍDA (markdown):
  ## Resumo (2 linhas)
  ## Destaques (3 bullets com números)
  ## Pontos de atenção (1-2 bullets)
  ## Recomendações (2 ações concretas)

Quando usar

Relatório semanal/mensal automático a partir de uma planilha de vendas, financeiro ou tráfego. Entrega que o cliente percebe valor na hora.

Pontos de customização

  • {{metricas}} — o que importa
  • Seções do relatório
  • Tom (executivo / técnico)

🤖 Skill: responder FAQ com base de conhecimento (RAG)

Responde perguntas usando só a base de conhecimento fornecida — o padrão RAG que evita alucinação.

SKILL: FAQ com base (RAG)               # v1.0
PAPEL: Você é o atendente de {{empresa}}. Responde com base na fonte.

BASE DE CONHECIMENTO (trechos recuperados):
"""
{{contexto_recuperado}}
"""

REGRAS:
  - Responda SOMENTE com o que está na base acima.
  - Se a resposta não estiver na base, diga:
    "Não tenho essa informação, vou te encaminhar para um atendente."
  - Cite o trecho usado entre colchetes [fonte].
  - Tom: {{tom}}   // ex: cordial e objetivo

Pergunta do cliente:
"""
{{pergunta}}
"""

✓ O que faz dar certo

  • ✓"Só pela base" + frase de "não sei" evita invenção
  • ✓Recuperar bons trechos antes (busca) é metade do trabalho
  • ✓Citar a fonte gera confiança e facilita auditoria

✗ Onde quebra

  • ✗Base mal recuperada = resposta errada com confiança
  • ✗Sem a frase de "não sei", a IA inventa
  • ✗Contexto grande demais dilui a resposta

💡 Dica prática

A qualidade do RAG depende mais da recuperação (quais trechos você injeta) do que do prompt. Comece com uma base pequena e bem organizada antes de escalar.

🔁 Como adaptar e versionar suas skills

Reuso é o que escala um negócio de automação. Você nunca começa do zero — adapta um template e versiona.

Fluxo de adaptação (passo a passo)

1

Copie a skill mais próxima e renomeie com o cliente: faq-paocia-v1.

2

Troque só os pontos de customização (papel, regras, categorias, formato). Não mexa no esqueleto.

3

Rode os testes de regressão (mesmas entradas, conferir saída). Só então suba a versão.

Cabeçalho de versão (cole no topo da skill)

# skill: faq-paocia
# v1.0  2026-06-02  base inicial (5 categorias)
# v1.1  2026-06-09  +categoria "entrega", limiar 0.6 -> 0.65
# v2.0  2026-07-01  schema de saída mudou: +campo "prioridade"
#
# CUSTOMIZAÇÕES deste cliente:
#   - categorias = [pedido, dúvida, entrega, reclamação]
#   - tom = cordial e curto
# TESTES DE REGRESSÃO: ver casos/faq-paocia.csv (8 casos)

Quando usar

Em todo novo cliente ou mudança de regra. Versionar evita "consertei aqui e quebrou ali" e mantém histórico de decisões.

Pontos de customização

  • Convenção de nomes (skill-cliente-vX)
  • Onde guardar o changelog
  • Conjunto de casos de regressão
