MÓDULO 3.3

🎯 Diseño de prompts y lógica de decisión

El prompt es el cerebro de la automatización con IA — y, como no hay una persona que corrija en tiempo real, tiene que estar bien desde el principio. Aquí diseñas prompts como especificaciones, fuerzas una salida en JSON validable, la proteges con guardrails, ramificas el flujo a partir de la IA e iteras con pruebas hasta confiar.

1

📝 El prompt como especificación

En la automatización, el prompt no es una conversación: es código en lenguaje natural. Se ejecutará mil veces por sí solo, sin nadie que corrija la IA en tiempo real. Por eso necesita una especificación: instrucciones precisas, sin ambigüedades, que definan exactamente el comportamiento esperado.

✓ Prompt de especificación

  • ✓Define el rol, la tarea y el formato exacto de salida.
  • ✓Cubre los casos límite ("si no hay datos, devuelve X").
  • ✓Se comporta igual en cada ejecución.

✗ Prompt conversacional

  • ✗"Ayúdame a analizar esto" — es vago, depende del contexto.
  • ✗No indica qué hacer cuando algo se sale de lo esperado.
  • ✗Da respuestas diferentes en cada ronda.

💡 Consejo práctico

Antes de escribir el prompt, pregunta: si le diera esta instrucción a un empleado nuevo, ¿podría ejecutarla sin preguntarme nada? Si la respuesta es no, el prompt todavía tiene vacíos.

Código

Funciona sola mil veces.

Sin ambigüedad

Necesitas tener certeza antes.

Bordes

Cubre lo inesperado.

Consistente

La misma entrada, la misma salida.

2

🏗️ Estructura de un prompt confiable

Una estructura fija hace que el comportamiento sea predecible: rol (quién es la IA), contexto (lo que necesita saber), tarea (qué hacer), formato de salida (cómo responder) y reglas (qué respetar). A continuación, el mismo patrón aplicado a un clasificador de pedidos.

🧾 Ejemplo de prompt estructurado

# ROL
Eres un clasificador de pedidos de un e-commerce.
Responde de forma objetiva, sin comentarios adicionales.
# CONTEXTO
Categorías válidas: compra, soporte, reclamacion.
Prioridades válidas: alta, media, baja.
# TAREA
Lee el mensaje del cliente y clasifica la categoría
y prioridad. Estima tu confianza de 0 a 1.
# FORMATO DE SALIDA
Responde SOLO con un objeto JSON, sin texto antes
o después, con las claves: categoría, prioridad,
confianza, justificación.
# REGLAS
- Si no puedes clasificarlo, usa confianca < 0.5.
- Nunca inventes una categoría fuera de la lista.
# MENSAJE
{{ mensagem_do_cliente }}

📐 Por qué funcionan las secciones con nombre

  • •La IA separa la instrucción (las reglas) del dato (el mensaje del cliente) sin confundirlos.
  • •Revisas y versionas cada sección de forma aislada.
  • •Se convierte en una plantilla: la misma estructura sirve para cualquier clasificador.

🧾 Salida estructurada (JSON) y validación

El texto libre rompe la automatización: el siguiente paso no sabe dónde está cada dato. Forzar JSON con campos fijos e validar la respuesta antes de usarla es lo que hace que la salida de la IA sea lo bastante confiable para alimentar una acción automática.

📤 Salida JSON esperada

{
  "categoría": "reclamación",
  "prioridad": "alta",
  "confianza": 0.92,
  "justificación": "el cliente menciona un retraso y pide un reembolso"
}

✅ Validación antes de usar (pseudocódigo)

# 1. ¿es JSON válido?
datos = parse_json(salida_ia)  # falló → repetir/escalar
# 2. ¿tiene todos los campos obligatorios?
exigir(datos, [categoria, prioridad, confianza])
# 3. ¿los valores están en la lista permitida?
si datos.categoria no está en CATEGORIAS: rechazar
# 4. solo entonces pasa a la decisión

⚠️ Atención

Nunca confíes ciegamente en la salida de la IA. Si el JSON viene malformado o con una categoría inventada, la validación debe rechazar y repetir (o escalar); jamás dejes que un valor no válido siga hacia una acción automática.

JSON

Campos fijos y con nombre.

Validar

Lista

Rechazar

No válido → repetir o escalar.

🚧 Guardrails y fallback

La IA comete errores y alucina. Salvaguardas son los límites — lo que no puede hacer, lo que la validación rechaza. Fallback es lo que ocurre cuando no está segura: pedir confirmación, escalar a una persona o usar un valor predeterminado seguro. Juntos, impiden que un error se convierta en una acción irreversible.

1

Salvaguarda en el prompt

Instrucciones explícitas sobre lo que nunca debe hacer: no inventar categorías, no tomar decisiones fuera del alcance, indicar poca confianza cuando haya dudas.

2

Salvaguarda en la validación

Comprobación programática que rechaza salidas fuera del formato o de la lista de valores: la IA propone, el código verifica.

3

Fallback por confianza

Cuando la confianza está por debajo de un límite (ej.: 0.6), el flujo se desvía a revisión humana en vez de actuar por sí solo.

💡 Consejo práctico

Pídele a la IA un campo confianza en cada salida y úsalo como disparador de fallback. Es la forma más sencilla de convertir «la IA no está segura» en una decisión concreta del flujo: actuar por cuenta propia solo por encima del límite y escalar por debajo.

Limitar

Qué no puede hacer la IA.

Confianza

5

🔀 Lógica de ramificación basada en la IA

Aquí es donde la IA deja de ser un adorno y se convierte en el cerebro: un campo categórico de la salida JSON (p. ej.: categoría o prioridad) se convierte en la clave de un IF/switch en el flujo, dirigiendo cada caso a una acción diferente. La IA clasifica, el flujo ejecuta.

📐 Reglas de una ramificación saludable

  • •Usa un campo categórico (lista cerrada) como clave; nunca texto libre.
  • •Ten siempre un rama predeterminada para el caso que no coincide con ninguna opción.
  • •Combina con confianza: la categoría correcta + una confianza baja aún pueden escalarse.
La IA decide

El flujo se ejecuta.

Clave

Campo categórico cerrado.

Patrón

Rama para el resto.

Combinar

Categorías + confianza.

🔁 Probar e iterar el prompt

Un prompt que acierta en un ejemplo puede fallar en diez. Arma un conjunto de casos de prueba — incluidos los difíciles y adversariales: ejecuta el prompt con todos, mide la tasa de aciertos y ajústalo hasta que se estabilice. Solo este ciclo te da confianza para dejar que la IA tome decisiones por sí sola en producción.

1

Reúne casos reales

Toma mensajes reales del proceso (de la auditoría de la T2), incluidos los ambiguos y los que suelen causar confusión.

2

Define la respuesta correcta

Para cada caso, anota cuál sería la salida correcta. Esa plantilla de referencia es la regla con la que mides el prompt.

3

Ejecuta, mide, ajusta

Ejecuta el prompt en todos los casos, compáralo con la respuesta correcta, calcula la tasa de aciertos y ajusta el prompt donde haya errores. Repite hasta que se estabilice.

✓ Iteración saludable

  • ✓Incluye casos difíciles y adversariales desde el inicio.
  • ✓Mide la tasa de aciertos antes y después de cada ajuste.
  • ✓Deja de iterar cuando la tasa se estabilice, no en el primer intento.

✗ Iteración ingenua

  • ✗Lo prueba solo con un ejemplo fácil y lo da por terminado.
  • ✗Ajusta según tus suposiciones, sin medir si mejoró.
  • ✗Corrige un caso y rompe tres sin darte cuenta.
Conjunto

Varios casos, no uno.

Difíciles

Medir

Estabilizar
