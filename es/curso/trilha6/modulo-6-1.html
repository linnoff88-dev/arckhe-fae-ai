🍞 Briefing: Panadería Pêo&Cia

Panadería de barrio, 12 empleados, 1 dueña (Marta) que se encarga de la administración. Vende en el mostrador y por WhatsApp. Recibe ~40 pedidos al día por WhatsApp, emite facturas manualmente, controla el inventario en una hoja de cálculo y responde las mismas dudas de los clientes todo el día.

Usa este contexto en los seis ejercicios. Cuando haya un número, inventa uno plausible y sé consistente.

🎯 Busca 3 tareas de 10 horas

Tu misión: encontrar, en la Panadería Pêo&Cia, tres tareas repetitivas que suman unas 10 horas por semana y son buenas candidatas a la automatización.

🎯 Objetivo

Salir con una lista de 3 tareas, cada una con frecuencia, duración y nivel de dificultad — lista para convertirse en un proyecto.

Paso a paso

1

Enumera todo lo que hace Marta en un día normal (anota al menos 10 actividades).

2

Para cada una, estima frecuencia (x/semana) y duración (min/vez).

3

Multiplica para calcular las horas por semana y marca el «dolor» (1–5). Elige las 3 con más horas × dolor.

✅ Criterio de "listo"

Tienes 3 tareas, cada una con horas por semana calculadas y un nivel de dolor de 1 a 5, y la suma de las tres queda entre 8 y 12 horas.

📊 Auditar y calcular el ROI

Toma la tarea ganadora del ejercicio 1 (responder WhatsApp) y calcula el retorno de automatizarla.

🎯 Objetivo

Llegar a una cifra de ROI y payback que justifique (o no) el proyecto.

Fórmulas que vas a usar

economia_mensal = horas_mes_economizadas × custo_hora
roi_%           = (economia_anual - custo_projeto) / custo_projeto × 100
payback_meses   = custo_projeto / economia_mensal

✓ Hazlo así

  • ✓Usa el costo por hora con cargas (salario + cargas sociales), no el salario bruto
  • ✓Cuenta solo las horas que la automatización realmente te ahorra
  • ✓Incluye el costo de la API/herramienta en el costo del proyecto

✗ Evita

  • ✗Inflar el ahorro suponiendo un 100% de automatización
  • ✗Olvidar el costo mensual de mantenimiento
  • ✗Ignorar el tiempo que queda para la revisión humana

✅ Criterio de "listo"

Tienes el ahorro mensual, el ROI anual en % y el período de recuperación en meses, con todas las premisas anotadas.

Ejemplo de respuestas

Premissas
  horas_mes (WhatsApp)      = 20 h
  % automatizável          = 70%  -> economiza 14 h/mês
  custo_hora (Marta)       = R$ 45
  custo_projeto            = R$ 2.500 (build) + R$ 120/mês (API+ferramenta)

Cálculo
  economia_mensal = 14 × 45            = R$ 630/mês (bruto)
  economia_líquida = 630 - 120         = R$ 510/mês
  economia_anual   = 510 × 12          = R$ 6.120
  roi_%  = (6120 - 2500) / 2500 × 100  = 144,8%
  payback = 2500 / 510                 = 4,9 meses

🗺️ Diagramar as-is → to-be

Mapea el proceso de atención por WhatsApp cómo es hoy (as-is) y cómo quedará automatizado (to-be).

🎯 Objetivo

Dos flujos lado a lado, que dejan claro qué pasos asume la IA.

Paso a paso

  1. Escribe el flujo actual como una secuencia de pasos (cada paso: actor + acción).
  2. Marca con 🤖 cada paso que una IA podría asumir.
  3. Reescribe el flujo to-be eliminando o condensando los pasos automatizados.
  4. Indica los puntos de decisión (donde se necesita un «sí/no»).

Ejemplo de respuestas

AS-IS (hoje)
  cliente → manda msg no WhatsApp
  Marta   → lê a msg
  Marta   → identifica o tipo (pedido? dúvida? reclamaçêo?)
  Marta   → responde manualmente
  Marta   → se for pedido, copia pra planilha   🤖
  Marta   → confirma valor e prazo               🤖

TO-BE (automatizado)
  cliente → manda msg no WhatsApp        [trigger]
  IA      → classifica (pedido/dúvida/outro)     🤖
  decisêo → é dúvida comum? --sim--> IA responde da base  🤖
                            --nêo--> encaminha p/ Marta
  IA      → se pedido, extrai itens e grava na planilha  🤖
  IA      → devolve confirmaçêo ao cliente              🤖

📐 Diseñar el blueprint

Transforma el to-be en un blueprint de una página: trigger, herramientas, modelo, lógica y acciones.

🎯 Objetivo

Especificación técnica suficiente para que alguien empiece a construir sin preguntarte nada más.

Plantilla de blueprint (completa)

BLUEPRINT — Atendimento WhatsApp Pêo&Cia
  Trigger     : nova mensagem no WhatsApp Business (webhook)
  Ferramentas : n8n · WhatsApp API · Google Sheets · modelo de IA
  Modelo      : LLM rápido/barato (classificaçêo) + 1 chamada p/ resposta
  Lógica      :
     1. classificar intençêo -> {pedido | duvida | outro}
     2. se duvida -> RAG na base de FAQ -> resposta
     3. se pedido -> extrair itens (JSON) -> append na planilha
     4. se confiança < 0.6 -> encaminhar p/ humano
  Ações       : responder cliente · gravar planilha · notificar Marta
  Pontos de falha: msg ambígua · item fora do cardápio · API fora do ar

📋 Checklist del blueprint

  • • ¿Tiene exactamente 1 trigger definido?
  • • ¿Cada decisión tiene un camino «si no»?
  • • ¿Hay una alternativa humana para los casos de baja confianza?
  • • ¿Están enumerados los puntos de falla?

🔧 Construir un flujo simple

Crea un flujo mínimo de 3 nodos: trigger → IA → acción. Aquí puedes construir algo real en n8n/Make o simularlo con pseudocódigo.

🎯 Objetivo

Un flujo que recibe un mensaje, llama a la IA y ejecuta una acción — de punta a punta.

Seudoflujo (copia y adapta)

// NÓ 1 — TRIGGER (webhook WhatsApp)
input = { from: "+55...", text: "quero 2 pêes de queijo e 1 café" }

// NÓ 2 — IA (extraçêo estruturada)
prompt = `Extraia o pedido como JSON do schema:
{ "itens":[{"produto":string,"qtd":number}], "obs":string|null }
Responda SÓ o JSON. Texto: ${input.text}`
ia_out = chamarLLM(prompt)        // -> { "itens":[...], "obs":null }
pedido = JSON.parse(ia_out)

// NÓ 3 — AÇêO (gravar + responder)
appendPlanilha("Pedidos", pedido.itens)
responderWhatsApp(input.from,
  `Anotado! ${pedido.itens.length} itens. Confirma? (sim/nêo)`)

💡 Consejo práctico

Prueba primero el nodo de IA por separado, con 3 mensajes reales diferentes, antes de conectar la acción. El 80% de los bugs está en el parsing del JSON.

El flujo se ejecuta con 3 mensajes de prueba diferentes y registra o responde correctamente al menos a 2.

💼 Armar una propuesta comercial

Empaqueta todo en una propuesta de 1 página para Marta: problema, solución, ROI, precio y próximos pasos.

🎯 Objetivo

Una propuesta que ancla el precio en el ROI del ejercicio 2 y termina con un CTA claro.

Plantilla de propuesta (completa)

PROPOSTA — Atendimento automático no WhatsApp
Para: Marta · Padaria Pêo&Cia

1. O problema
   ~20 h/mês respondendo as mesmas dúvidas e lançando pedidos à mêo.

2. A soluçêo
   Assistente no WhatsApp que classifica, responde dúvidas da base e
   registra pedidos na planilha automaticamente. Você só revê exceções.

3. Resultado esperado
   ~14 h/mês liberadas · menos erros de lançamento · resposta em segundos.
   Economia estimada: R$ 510/mês líquidos · paga em ~5 meses.

4. Investimento
   Setup: R$ 2.500 (única vez) · Manutençêo: R$ 120/mês.

5. Próximo passo
   Aprovaçêo até [data] -> entrego rodando em 2 semanas.
   Responda "topo" para começarmos.

⚠️ Atención

Nunca fijes el precio según el costo de tu hora. Fíjalo como una fracción del valor que obtiene el cliente. Aquí el precio (R$ 2.500) es menos de la mitad del ahorro anual, así que es fácil decir que sí.

Propuesta de 1 página con las 5 secciones, precio basado en el ROI y un CTA con fecha y una acción clara.
