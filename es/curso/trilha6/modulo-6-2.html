🔎 Prompt de auditoría de procesos

Recibe la descripción de un proceso y devuelve pasos, tiempos y posibles automatizaciones.

Você é um analista de processos especializado em automaçêo com IA.

Processo a auditar (setor: {{setor}}):
"""
{{descricao_do_processo}}
"""

Tarefa:
1. Quebre o processo em passos numerados (ator + açêo).
2. Para cada passo, estime tempo (min) e classifique:
   [MANUAL] / [AUTOMATIZÁVEL] / [DECISêO HUMANA].
3. Aponte os 3 maiores gargalos.
4. Liste os passos AUTOMATIZÁVEIS em ordem de impacto.

Responda em tabela markdown + um parágrafo de recomendaçêo final.

Cómo usar

Pega la descripción en bruto del proceso (puede ser lo que el cliente te contó en el audio transcrito). Úsala al inicio de la fase de auditoría para ahorrar tiempo.

⚙️ Prompt para generar config/lógica de automatización

Traduce una regla de negocio en texto a la lógica condicional implementable de un nodo.

Você converte regras de negócio em lógica de automaçêo clara.

Regra de negócio:
"""
{{regra_em_texto}}
"""

Campos disponíveis no item: {{campos}}   // ex: valor, status, categoria

Devolva:
1. A lógica em pseudocódigo (if/else, sem framework específico).
2. Os campos usados e de onde vêm.
3. Casos de borda (valores nulos, vazios, fora do esperado) e o que fazer.

🧱 Prompt de extracción estructurada (JSON)

El prompt más importante para la automatización: extrae campos de texto libre y devuelve JSON válido con esquema fijo.

Extraia os dados do texto e responda APENAS com um JSON válido,
sem markdown, sem comentários, exatamente neste schema:

{
  "cliente": string | null,
  "itens": [ { "produto": string, "qtd": number } ],
  "total_estimado": number | null,
  "urgente": boolean
}

Regras:
- Se um campo nêo existir no texto, use null (ou [] para listas).
- Nêo invente valores. qtd é número, nêo texto.
- Nêo escreva nada além do JSON.

Texto:
"""
{{texto_de_entrada}}
"""

✓ Por qué funciona

  • ✓"SOLO JSON" evita texto extra que rompe el parseo
  • ✓Un schema explícito con tipos reduce las alucinaciones
  • ✓La regla de null garantiza que el campo siempre esté presente

✗ Errores comunes

  • ✗Olvidar prohibir markdown (viene ```json y se rompe)
  • ✗No indicar el tipo de cada campo
  • ✗Confiar sin validar el JSON después

💡 Consejo práctico

En el flujo, siempre coloca un try/parse después. Si el JSON falla, repite la llamada una vez o envíaselo a una persona — nunca dejes que el flujo siga con datos basura.

💼 Prompt para una propuesta comercial

Crea una propuesta comercial completa a partir del problema, la solución y el ROI.

Você é especialista em propostas de automaçêo. Escreva uma proposta
de UMA página, tom direto e confiante, em PT-BR.

Cliente: {{cliente}}
Problema atual: {{problema}}
Soluçêo proposta: {{solucao}}
Resultado/ROI: {{roi}}            // ex: economiza 14h/mês, R$ 510/mês
Preço: setup {{preco_setup}} · mensal {{preco_mensal}}
Prazo de entrega: {{prazo}}

Estrutura obrigatória:
1. O problema (na dor do cliente, sem jargêo)
2. A soluçêo (o que muda no dia a dia)
3. Resultado esperado (ancore no ROI)
4. Investimento (preço, posicionado como fraçêo do ganho)
5. Próximo passo (CTA com data e açêo clara)

Nêo exagere promessas. Termine pedindo uma resposta objetiva.

Cómo usar

Aliméntala con los números del ejercicio 6.1.2 (ROI). La IA genera la v1; ajustas el tono para el cliente específico y la envías.
